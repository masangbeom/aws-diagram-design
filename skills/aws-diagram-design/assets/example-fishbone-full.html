Orders API ALB 5xx · Root-cause fishbone

Five candidate cause categories investigated after a 40-minute spike of ALB 5xx errors on the ECS orders service. The confirmed root cause carries the diagram's only accent — everything else stays in the neutral ink/muted palette so the reader's eye lands on the answer, not the investigation.

ROOT CAUSE

Data — missing Aurora index

No index on orders.created_at; the Aurora query planner fell back to a sequential scan once the table crossed 3x its forecast size, so ECS tasks held connections past the ALB timeout. The single confirmed cause — every other category was ruled out.

Contributing categories

Deploy (CodeDeploy canary skipped, task definition drift), ECS / Fargate (pool cap 20, CPU at 85%), and Observability (no CloudWatch p99 alarm, 5-minute metric period) all slowed detection but didn't cause the regression themselves.

People

A mid-incident on-call handover cost roughly ten minutes of context — worth fixing, not the root cause.
