Iceberg table storage · Capability radar

Four AWS storage options for an Apache Iceberg lakehouse, scored 0–10 across five workload dimensions. The chart is a decision tool — the recommended option carries the only colored fill; everything else sits in the muted comparison palette.

RECOMMENDED

S3 Tables

9 across the board, weakest only on large-object reads. The clear pick when small-file performance and Iceberg integration matter — compaction and snapshot cleanup run as a managed service, not as your own Spark jobs.

S3 general purpose

The reference store: top-class on large-object reads and write throughput, but a hard step down on operational simplicity once you own Iceberg compaction, orphan-file cleanup, and bucket policy sprawl.

HDFS on EMR

Capable across the board, but the lowest score on operational simplicity. Pick it when an existing Hadoop estate is lifted onto long-running EMR clusters — not for a fresh greenfield.

FSx for Lustre

Solid middle path: an S3-linked file system with fast large reads, but no standout dimension — which is itself an answer when the team optimizes for "boring, managed, fine."
