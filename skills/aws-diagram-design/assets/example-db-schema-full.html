Aurora PostgreSQL · commerce schema

The physical schema behind checkout on Amazon Aurora PostgreSQL: five tables, real SQL types, and foreign keys that anchor column to column, not box to box. Customers carry their Cognito user ID; invoices point at PDFs in Amazon S3. The dashed group marks the non-default billing schema.

THE DESTRUCTIVE EDGE

Deleting an order cascades

order_items.order_id is the one ON DELETE CASCADE in this schema — remove an order and its line items go with it. Every other foreign key is RESTRICT.

Column to column, not box to box

  • Every FK anchors to a specific row on both ends
  • Fixed 24px row height keeps anchors predictable
  • The ON DELETE label is the point of the edge

Scoped to the subsystem

products truncates to a + 3 more columns row rather than dumping every column. This is checkout, not a \d+ of the whole Aurora cluster.
